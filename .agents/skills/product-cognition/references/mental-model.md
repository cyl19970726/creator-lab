# 业务因果与判断模型

这份模型用于产生和检验设计约束。它应能在尚无页面时解释业务怎样成立，也能在条件变化时指出原方案哪里需要改。下面是推导操作，不是必须输出的章节清单。

## 先解释价值怎样产生、怎样积累

从业务目前怎样做、哪里付出代价、要获得什么改变开始。区分长期业务目的、产品承担的责任和眼下任务；技术设施只是实现机制，需解释它解除什么障碍。

沿一次真实工作恢复起点、参与者、材料、产出和使用结果。再检查重复使用后什么会留下并影响下一次：可复用方法、经验、关系、信誉或其他业务对象。若声称系统会学习，说明哪些证据由谁解释，通过什么改变影响以后结果；记录数量增加不是学习的证明。

根据产品识别有关循环及其连接。例如做一次业务与改进做事方法，可能依赖同一批结果，却有不同对象、时间跨度和结束条件；新增底座能力又可能由另一个项目负责。不要将多个循环压成所有人必须依次走完的一条向导，也不要为了有“闭环”强造循环。

每个关键转换解释：前提、动作或决定、责任者、产生的事实，以及下一段为何能够据此继续。保留分支、失败、暂不改变和并行存在的可能；只检查会影响当前判断的情况。

## 从目标独立找出关键判断

设想产品已经被交给使用者。即使他暂时不点击任何按钮，为了继续承担业务责任，必须能回答哪些问题？谁需要回答、何时需要、判断错误会造成什么？从这里产生任务，不从现有页面名称反推。

例如，场地预约产品中，“这次能否预约”与“哪些场地值得继续开放”需要不同范围的证据：前者需要准确时段、条件及占用事实；后者可能需要一段时间的使用、取消、成本与需求。不能因为两者使用同一事实源，就认为支持一个已自然支持另一个；若产品只负责预约，后一个责任仍应作为范围提案核实。

从每个重要判断逆推：

- 作判断需要什么事实或内容，证据属于哪个准确对象和条件？
- 范围是一份成果、一次尝试、一组案例，还是一段历史？纳入或排除什么，未知与失败是否可见？
- 事实如何产生、由谁解释？原始结果、评价、原因假设与采用决定能否分清？
- 判断改变什么对象或后续工作；没有足够证据时，怎样保留未知并继续？

证据可以存在于内容、行为或人的判断中，不要求一律量化、存数据库或自动裁决。写出会改变设计的依赖即可，不强制给每个判断建立记录模板。

## 检查对象，而不只检查动作

找出在业务中持续有身份、会被返回查看或引用的对象。对其中关键者，尝试把它作为认识起点：它为什么存在、具体是什么、被怎样使用、产生了什么、判断依据是什么、后来如何变化？这些问题的相关程度由业务决定，不能套成所有对象的固定详情页。

尤其核对会改变信息范围的关系：一个对象多次使用、一项工作尝试多种方法、一个结果被多处引用、多个候选并存、目标或标准发生变化。区分对象身份、准确内容、一次发生和观察集合；时间先后不自动说明生产、依赖、评价或继承关系。

把**预期机制、实际事实、对事实的解释、作出的决定**分开。计划有输出不代表实际产生，获得好结果不证明机制正确，一条评价不等于采用，一次改动不等于改进。需要的图或列表应服务这些不同语义，而不是合成一张含糊的“全流程图”。

对象只是筛选条件还是完整工作上下文，要看它承载的判断。若使用者需围绕它持续查看多个相关方面，并保证相同范围，它就需要一个可持续进入的上下文；上下文可以由页面、画布、选择器或其他方式提供，不能据此直接指定侧栏树。

## 用变化和删除检验推论

选择会改变本轮结论的条件，作简短检验：目标变了，历史评价还适用吗？标准变了，结果变好能否归因于方法？新方案失败时，原来可用的成果和生产工作能否继续？不必穷举所有状态。

对拟加入的关系做删除检验：如果拿掉它，哪个已有目标或关键判断会失去依据，或者哪些事实会混淆？指出一个具体后果，并寻找其他更轻的实现也能满足它。由此区分：

| 判断 | 处理方式 |
| --- | --- |
| 已确认要求或由业务判断推出的必要关系 | 保留依据，转成设计必须支持的任务；本轮不做时明确依赖与暂缓 |
| 一种可能的呈现、机制或方便功能 | 作为可替代方案比较，不写成业务必需 |
| 需要额外事实、价值偏好或因果证据 | 标明未知及其影响，按必要程度补证或向用户澄清 |

“所有产品都应该有”“可能以后有用”不足以证明必要。用户提出的方案也可能只是一种满足目的的方式；可以给出有理由的替代，但已明确的选择应尊重。

## 把模型落实为可检查的设计责任

进入设计前，留下本轮最重要的判断任务及其范围。完成设计后，让不了解作者解释的人沿同一任务复原对象、证据与后续决定。原型没有支持某项任务时，说明是关系模型缺失、条件未知、范围暂缓还是呈现断点；不要只增加一个同名栏目。

新反馈到来时，回看它改变了哪条假设或关系，以及哪些决定、设计与验证依赖它。如果早已知道却没有使用，修复的是承接与验收；若是新的业务事实，则更新模型。两者都不能只在正文末尾追加“补充理解”。
