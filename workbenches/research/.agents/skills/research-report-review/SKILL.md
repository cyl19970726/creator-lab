# 独立报告审核

你不编写被审产物；读用户目标、当前文件和原始证据。根据research-report-workflow/references/contracts.md写review.json，绑定文件哈希与实际检查表面。缺输入明确指出，不从作者“已通过”继承结论。

在本项目 workflow 的模型审核调用中，只输出标题、可读审核说明、decision 和 findings；不输出 target 或抄写候选哈希。工作流以实际提交给你的候选精确身份绑定审核回执；如果自定义审核器显式给出冲突身份，合同会拒绝该回执。独立使用本 skill 写文件时仍按所用文件的真实哈希记录审核范围。

## 模式

**outline**：核心问题覆盖、原理骨架、前置知识、验证计划。此时不要求全量证据，不能提前批准尚无数据的结论。

**foundation**：先核对研究综合是否回答 brief 的核心问题，区分事实、机制、框架与假设，再检查支撑主张、机制和计算。分别给出能否进入成稿及需补证事项，不以局部事实正确推断整个研究充分。此时尚未制作代表图源或进行独立读者复述；这些属于 A3，不能作为 A2 通过前提。实际渲染由宿主阅读器承担。综合稿若已包含错误图、错误公式或过强断言，仍须指出并修复。

**final**：读当前完整报告和收到的 Mermaid 图源，检查摘要与细节一致、问题与缺口真实处置、所有关键结论及变化影响。可继承未改变的foundation结果，不能继承改变了的文件版本。没有收到渲染截图时不声称已检查视觉呈现；宿主另做浏览器实际画面检查。

审核时按输入的 stageContract 判断当前阶段拥有的产物。研究员真实核验的原始页面与来源日期可作为证据；审核者自己未浏览不能抹掉研究员已留下的可核验定位。检索未发现新发布只能支持“在实际核验范围内未见”，不能证明绝对不存在；也不能要求某个日期窗口必然出现新公告来证明没有更新。brief 允许限定结论时，已披露且不影响核心回答的非核心未知可保留，不能因此自动阻止进入 A3。缺少支撑核心主张的证据仍应阻断。

## 检查顺序

1. **目标**：是在回答用户问题吗？是否把原理报告改成购买结论、营销叙事或知识索引？深度不足看缺少什么解释，不看字数。
2. **证据**：关键主张是否能找到原始支持？同源转述算几源？理论一致性是否被冒称独立实测？没有发现是否被写成不存在？原始来源/实测不可访问就记录限制。
3. **比较**：模型/软硬件/负载/计时/精度/缓存/样本/质量是否对等？不同组是否明示？参数匹配是否被升级成商品和售价等价？单项机制是否偷用了组合栈收益？
4. **推导**：独立重算关键公式与排名，核单位、方向、上下界、假设、敏感性。检查理论假设是否为了拟合实测而选择；经验范围不当硬物理上限；整机/裸卡成本混用；固定费被错误同比缩放；条件概率重复折损。
5. **表述**：实际配置不是最低门槛；能跑不是稳定；局部缺口与全篇绝对结论是否冲突；图表中的“唯一/最优/不可能”是否有完整依据。
6. **理解与问题**：读者提出的核心断点是否有准确解释？known_gap是否仍影响核心承诺？账本“有去处”不等于verified_answer；疑问者的猜测也要验证。
7. **呈现与版本**：检查本次收到的正文与图源中的数字、条件、来源叙述。若收到实际渲染图才检查其视觉呈现；没有则把视觉检查留给宿主浏览器。确认依赖变更的正文与图源已复验，不把局部检查外推到全文。

报告 verdict 必须说明目标覆盖与证据强度，而非仅列已关闭的问题。技术正确性、读者理解和主编整体交付判断分别记录；任一局部通过不能外推为用户接受。候选选题的表达限制不应成为削减母报告研究深度的理由。

## 判断和返工

阻断：改变核心结论的错误/不可支持断言、目标缺失、关键审核版本不匹配。非阻断：不影响主要理解的局部表达等，按本次交付范围处理。

发现必须含位置、可复现证据、影响和最小修复。区分“从文内可证明错误”“需查外部事实”“仅改进建议”。不把所有未知都变成新研究任务；允许准确的条件结论。作者修复后由你复验，不由作者自签关闭。

一次命中表面不够：补答正确但旧总纲仍错、数字修了但图注还是旧机制，都应重开。若反复出现同根因，回到假设/数据模型修正，而非继续补答。

输出accepted、accepted_with_limits或changes_required，并列真实检查边界。不可用“lint 0 errors”、所有Q出现、自己声称独立或达到轮次上限作为通过理由。本skill不授予外部发布/商业行为权限。
