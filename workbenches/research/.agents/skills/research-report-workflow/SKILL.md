# 深度研究报告路由

结果是读者能理解机制、追溯证据、复算主要结论，并知道结论的适用范围。报告的完整性由目标所需的解释与证据决定；不以字数、图数、来源数量或疑问框数量验收。本套是基于用户实际审阅经历定制的初版，尚非跨项目验证过的通用成功方法。

先读 [产物与审核合同](references/contracts.md)。恢复已有目标、报告、问题账本和当前版本；用户已经回答的口径直接沿用。历史文件只作为待核查材料，不继承旧审核结论；本路由不能继承“理论是独立第三源”“问题有去处即闭合”“已匹配参数即可套商业价格”的旧判据。若项目有另行接受的冲突规则，指出具体冲突，不能静默混用。

## 执行入口与加载

先按交付物和主张强度选择范围：正式深度报告使用本路由；普通单问解释可按需使用机制分析与证据核对，不强制生成整套报告文件或安排多轮独立审阅。需要判断现实表现、规模或主因时，应补相应实证，不能因为回答短就降低证据标准。

路由表中的“调用”指执行者在首次进入对应工作时实际读取该 skill 的 SKILL.md 及必要引用，不是仅在派工中提到名字。已在当前上下文完整读取且未变化的内容无需重复读。委派时给出项目内路径、核心问题、适用方法、已有证据与交付目标；由承担该工作的 Agent 读取，主编不以自己读过替代对方读取。文件缺失先定位，不静默跳过或声称已调用。

在当前运行的资产、步骤与审核记录中保留实际使用的方法版本和产物。读取记录不证明方法有效，仍以实际研究和审阅结果验收。

## 角色与独立性

- 主编/协调者：维护目标、范围、骨架、当前产物索引，整合正文，派发精确输入，处理返工。
- 机制研究员：模型或对象的原理、约束、公式、部署/改动为什么有效。
- 实证研究员：来源、实际配置、负载、测量、冲突与空白。可和机制研究并行交换问题。
- 图文作者：把已核对的机制和数据呈现为可读图文，维护图文一致。
- 读者疑问者：代表目标读者提出困惑，检查修复后能否理解；不裁决科学真伪。
- 独立审核者：校验证据、数学与因果、比较条件、结论边界和当前成品；不修改自己审核的产物。

这是职责分工，不要求固定六个常驻Agent。主编可兼图文作者，小题可由一位研究员承担两类研究；独立审核不能由该被审产物作者冒充。疑问者需独立阅读，不预先喂作者的辩护。复杂数理可增专项Reviewer，不固定模型品牌/档位。不能派独立Agent时如实标自查，未满足独立审核条件。

## 工作台上的三个研究交付步骤

沿用本项目工作台阶段：A1 对齐目的与必要边界 → A2 分题研究并汇合证据 → A3 架构、图文与疑问闭环。下表是步骤内部工作，不是另外多个阶段或必须独立派发的 Agent。A2 内先做最小预研与探索骨架，再分题研究、综合认知并按缺口补证；A3 根据综合结果确定正式架构、完成图文和审阅。探索骨架用于提问，不是必须填满的成稿目录。当图承担核心机制解释时，先产出一张实际可看的代表性因果图，标清对象、位置、操作、状态和返回关系；独立读者只看真实图文复述，再决定是否扩展全稿。保存原始复述，不用作者自述“通俗易懂”代替阅读证据。A3 接受者可以是用户明确授权的代理，须记录真实角色、版本和范围。

在本项目接续研究时，从宿主提供的已核验资产读取选题归属、本期上下文、当前精确版本和未结意见；完成后将真实产物与决定接回同一内容记录。不能只更新本地报告索引而让工作台继续指向旧版本。

## 生产与Review路由

| 步骤内工作 | 调用 | 输出与去向 |
|---|---|---|
| 0 定义任务 | 本路由 | brief.md：读者、用途、核心问题、已知偏好、范围、交付深度 |
| 1 最小预研与探索骨架 | research-report-architecture + research-reader-questioner + research-report-review（outline模式） | outline.md、原理关系图草案、章节/问题/图/数据需求映射 |
| 2 采证与推导 | research-evidence-synthesis + research-mechanism-analysis | claims.json、sources.json、benchmarks.json、mechanisms.md、calculations.json、gaps.md |
| 3 综合认知与补证 | 本路由主编 + research-evidence-synthesis + research-mechanism-analysis | synthesis.md（或现有等价研究汇总）：核心回答、依据、冲突、未知、假设变化、补证决定；必要时回步骤2 |
| 4 成稿判断与正式架构 | research-report-review，foundation模式 + research-report-architecture | 审核核心回答及推导；根据综合结果修订outline.md，不把探索骨架直接当定稿结构 |
| 5 图文成稿 | research-report-composition | report.md、figures/、dependencies.json；重大复杂图先做一张样例 |
| 6 读者验证 | research-reader-questioner | questions.json，作者修复后疑问者复读，技术问题交Reviewer |
| 7 定稿审核 | research-report-review，final模式 | review.json：当前版本、表面、发现、状态与复验 |
| 8 交付与下游 | 本路由 | release.md、证据和产物快照、未决项及影响；下游另按其方法执行 |

### 综合认知与进入成稿的依据

主编对分题结果进行交叉综合，不把多份材料拼接当作综合。围绕 brief 中每个核心问题说明：当前回答是什么；哪些来源、条件和推导支持；属于观测事实、来源报告、机制推导、分析框架还是待验证假设；与其他分题有无冲突；哪些发现改变初始假设；剩余未知影响什么。跨系统/尺度的结论必须有连接两端的证据或明确的推导假设，不能用分别成立的两段描述代替因果联系。

根据未知对核心回答的影响选择补证，而非固定 Agent 数、案例数或研究轮次。非核心未知可保留为限制；核心问题仍只有名词分类或“视情况而定”时，说明能回答哪些条件、缺少哪些证据，继续必要研究或提出范围取舍，不包装为已经研究明白。

进入成稿前，独立审核者检查这些核心回答是否达到本次目标及证据强度，主编据此决定继续补证、限定范围交付或进入成稿，并记录理由。机制科普可以以有依据的解释框架为成果；判断现实主因、频率、规模或排序则需要相应实证，不能用框架替代。探索图与局部草稿可以提前帮助思考，不等于全稿已具备交付依据。

母报告保留目标所需的机制、数据、推导和比较条件；候选选题、平台时长与视频篇数不能反向删减研究。报告仍需解释清楚，清楚不等于简短。正式架构由研究结果决定；后续再提炼可支持的选题及表达，不因一条报告通过就自动批准所有下游内容。

骨架阶段先做少量真实预研以避免空拟目录；无需完成全部研究才给大纲。骨架草案调用疑问者检查大问题，并由独立审核者检查骨架是否支持用户目标。用户已明确的“三件事”直接作为结构基准，不反复申请批准。只有新发现导致核心范围或用途发生实质取舍，才让用户决策。

采证与机制推导互相校正：异常数据可能推翻假设，理论不符先检查测量和推导双方。证据不足可以形成限定结论的报告，不能靠想象填满矩阵。缺口若使核心承诺不可成立，须缩小承诺（范围改变需用户决定）或标未完成；非核心缺口诚实披露不无限阻塞。

## 用户报告审阅

定稿独立Review与必要修复后，交用户查看当前完整报告及审核修改记录。用户批改按影响返回局部正文、补充探索或报告架构；核心产物均保留版本关联。当前授权接受者（用户或明确授权代理）接受报告版本之后才交视频设计阶段，不以Agent pass推断用户已确认。

## 返工和停止

Reviewer给出最早错误源、受影响结论和最小修复；作者修改，Reviewer复验。疑问者检查理解，专家检查正确，主编不能用改状态替代二者。普通修复自主完成；两轮同根因仍未收敛，重新检查输入、假设或职责，不继续加问答框。轮次预算耗尽是未收敛，不是通过。

主张、公式、价格口径或用户目标改变，沿dependencies.json使相关正文、图、机器数据及下游审核失效；不重审无关部分。报告自己的错误立即修，不等待文章/视频读稿批准。

完成必须区分：研究草稿、限定范围可交付、独立审核通过、下游可引用。输出状态如实附未决项；完成报告不等于支持其中所有商业建议，也不等于文章或视频已获发布授权。

## 可选入口：基于上一版反馈优化

用户要求改进已发布内容时，以反馈绑定的旧报告精确身份与原始意见为输入，保留旧稿可读。事实错误或原理缺口返回定向补证；理解断点进入表达修订。表达修订只能复用宿主核验过的旧任务书、综合和依赖证据；当前候选仍需独立读者与事实复验。逐条记录反馈处理、影响范围和新旧稿关系；不让评论取代科学证据，也不把代理复验当用户接受。
