# Video Learning Loop

输入是具体版本与发布时间、后台指标/截图、用户反馈和当前受众目标；按[版本合同](../research-to-video/references/contracts.md)记录。

1. 核对指标名称、时间窗口、平台、分母和样本。截图字段不清就保留未知；点赞不能代表内容深度或完播，100%点击率无分母不能证明封面优秀。
2. 分清观测、计算、假设。片长×平均播放比例只能给粗略平均观看估算，不证明所有人在该秒退出，也不是留存曲线。
3. 用户说太长时，先看一个视频承担几个问题、第一次答案何时出现，而非直接剪成固定秒数。保留必要深度的下限由观众完成一次判断决定。
4. 拆系列需重新写每条独立hook、主图、答案和边界，交`video-content-architecture`；不做时间平均切分。长片可保留为完整资料，不默认下架。
5. 下一版选一个主要编辑变化，记录预期指标、护栏、观察窗口与混杂因素。曝光来源/主题/美术同时变化时只能作综合观察，不能声称单因素因果。
6. 将用户已明确偏好记为其偏好；将Reviewer漏项记为待验证流程改进。单案例不包装成所有题材的规律，后续实际失败再收窄或强化skill。

交learning Review后继续用户已授权的下一版；如果只是复盘则交付下一步的具体决定，不擅自发布新片或开定时任务。没有平台数据也可以给可检验编辑假设，不能宣称效果已改善。

## Previous_version模式：独立反馈分析Agent

在研究或视频开题阶段也可调用，不只用于发布收尾。读取准确账号、作品ID/链接、发布时间、旧成片/转写/封面/报告版本；采集评论正文与楼中楼、时间、可见互动和采集范围，区分真实读者、作者回复、重复与广告，不主动发评论。保留原始定位；对外文档匿名化。读得到多少就记录多少，不能把截取热门评论说成全量。

后台指标保存原字段、单位、采集时间和统计窗口，区分完播率、2秒跳出率、平均观看时长和留存曲线。展示值2.8万是约数；未提供的分母/窗口不猜。评论是用户需求与理解的证据，不是技术主张正确的证据。

交付feedback-brief.md（观察、证据、假设、限制）及change-map.md：反馈ID→旧报告段落/视频时间→问题类型→严重性→研究任务→报告架构变化→视频架构/开头变化→负责人→验收方法。分事实纠错、原理缺口、部署需求、表达/节奏、包装承诺、无关反馈。搜集相关参考内容，记录实际时间轴与可借鉴机制，不照抄文案或用热度证明因果。

由主编依据该映射重写报告，独立研究Reviewer审事实，视频Reviewer审表达；反馈Agent不得自写自审冒充独立通过。保留未采到评论/未取得后台的缺口，继续其他研究；必要登录才请用户接管。记录真实Agent/session、输入版本、审核与修复产物，原生trace为执行证据；项目索引只链接记录，不复制成另一套执行日志。新视频未发布则只交改善假设与未来观察计划，不宣称完播已经提升。

## 发布后效果闭环

按docs/POST-PUBLISH.md增加48h_review模式：真实48小时后数据快照与独立learning Review，默认72/96小时补测，保留实际采集时刻、缺失字段与统计口径。比较发布前expectation.md与实际成片、数据、评论，输出支持/相反/不足与替代解释。评论回复是单独的0–48h互动操作，previous_version分析模式仍保持只读。
