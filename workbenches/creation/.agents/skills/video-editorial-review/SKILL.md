# Independent Video Editorial Review

审核者必须独立于候选稿作者。由总路由调用可用独立Agent，给它原用户目标、证据和实际候选文件；不只给作者摘要或希望得到的答案。本skill明确需要独立Review；不可用同一作者换口吻伪装。没有独立能力则标明限制，保留可复核建议，不签独立通过。

读取[交接合同](../research-to-video/references/contracts.md)和[产物、审核与协作记录合同](../../../docs/03-architecture/article-app.md)。选择当前模式，不把本轮通过延伸到未检查表面：

| mode | 必查表面 | 决定性问题 |
|---|---|---|
| evidence | claims, sources, calculations | 主张是否超证据、计算条件是否一致？ |
| architecture | script, key-pages, timing, B2目标平台布局说明与代表图 | 每段原理改变什么判断？首次价值具体是什么、由哪个画面/语句交付、何时出现？本期目标平台（Token经济猫当前为小红书、抖音、视频号；后文简称目标平台）的自有标题、图解、字幕与来源是否留在共同可读区域及安全余量内，并避开平台按钮和底部文案？ |
| hook | opening-script, opening-timing, proof | 开头具体交付什么新理解，画面/语句是否支持？再核对前10秒与30秒内的兑现时间。 |
| package | cover, thumbnail, title, opening-script | 题图文是否同一承诺，缩略图能否读清？ |
| sample | sample-video, audio, motion, 目标平台实际播放视图记录 | 动态与声音是否真正可理解，而非静帧精美？首次布局是否已在目标平台实际播放视图中验证自有标题、图解、字幕、来源与关键动作，并避开平台按钮和底部文案？ |
| final | final-video, audio, captions, synchronization, 已验布局及局部复验证据 | 当前导出是否忠于批准稿，关键事件是否看得清听得懂？成品是否延用已验布局，变化处是否已局部复验？ |
| release | final-video, package, platform-preview, open-issues | 核心来源缺口关了吗，账号/声明/文件是否正确？ |
| learning | analytics, version, observation-window | 分母与版本可靠吗，有没有相关性冒充因果？ |

## 审核方法

1. 先从用户原话写本轮验收合同；用户的新要求可能合法增加深度，不以旧“精简”规则否决。
2. 先独立阅读实际候选与证据并写初步判断，再参考作者理由和读者意见；不要默认现有结构不可改。检查承诺到最终答案的链。每个重要解释做删除测试：删掉会损失哪个判断？只正确但无用途的内容不应进正片。
3. 理解检查由未参与写作的读者只看实际图稿/口播，先不给技术答案或预期缺陷。记录原样复述与困惑：谁在做、改变什么、结果去哪、回答了什么问题？复述术语不等于理解。读者不判事实真伪；编辑读过证据后的自测不能替代这份无提示检查。模拟读者不是人类试播。
4. 检查作者容易忽略的相邻关系：封面与开头、图表与口播、价格与收入、单卡与双卡、样片与最终文件、旧审核与新稿。
5. architecture 模式逐目标平台对照B2布局说明和实际代表图，确认自有固定区域与安全余量服务共同可读性，且避开平台UI，未以固定像素冒充平台适配。sample 模式读取目标平台实际播放证据；目标平台带控件的播放预览可构成该证据，不要求公开提交样片。示意遮罩必须标模拟。final 模式核成品延用已验布局，布局或关键文字/动作变化时核对受影响表面的局部复验。任何播放预览都不能证明已获提交或发布授权。
6. 不把用户原话中的技术假设当事实。区分合理直觉、精确机制和实际测量；只补足本片判断所需的校正。
7. 发现写具体位置、物证、观众影响、最小修复、复验表面。分blocking和non-blocking，列keep/cut/补充；质量分不能覆盖blocking。

## B2 核心草案与完整包的不同审阅范围

核心草案按本期风险选择实际资产，不要求作者先补齐全稿才审核。分别判断讲法是否成立、首次收获是否具体、自然试读何时兑现；更早出现一句正确但空泛的答案，不能单独关闭认知问题。允许否定核心方案，指出应返回的最早决策点；技术边界等有效部分保留。

图面检查对象、位置和足够的前后变化，分清画面实际传达与依赖作者解释的内容。素材检查认知作用及实际状态，不按实景/生成片段数量判丰富。收到完整包时再核新增内容、题图开头一致性、相邻段落和整体连续性；不重复无变化的全审，也不把核心局部通过外推完整设计或成片。

Review 的 surfaces、unchecked 和 allowed_next_action 写明“核心草案可继续扩展”或“完整包可交授权接受者审阅”等实际范围；维持现有 mode/JSON 合同，不新增评分门槛。内部通过不代替设计接受。

## 退出与复验

输出`pass / revise / insufficient-evidence / human-decision`之一以及allowed_next_action。不足只阻止受影响的下一步：缺原帖可以继续本地试片，不能因此直接发布该外部断言。不要把未来平台数据未到当当前制作阻断。
作者负责修复，Reviewer写新记录复验，旧Review不可覆盖。至少检查修改区及它影响的上下游；未实看的表面列unchecked，禁止填写已看。
两轮同类问题仍未收敛，回查输入或升到具体取舍，不堆更多评分。主观偏好已有就复用；未知重大选择才交用户。

写Review JSON，inputs列所有判词依赖文件的当前SHA-256，native_record写本次真实执行来源。运行：

```bash
python3 scripts/check_review.py /absolute/review.json --stage architecture --author-id actual-author
```

脚本仅验证完整性、独立身份声明、阶段和输入未变，不能验证诚实、实际视听能力或审美质量。它必须由真实Review先产生输入，不能作者自行填pass后拿脚本当审核。
