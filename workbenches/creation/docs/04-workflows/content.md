# 内容迭代：在完整稿里检验问题和解释

## 本质问题

这份完整内容是否兑现创作者希望读者获得的理解？准确、可复述一句结论，仍可能没有讲懂。判断需回到具体必答问题，查看稿子里的实际解释和冷读者仍然存在的疑问。

## 输入与产物

输入：`topicId`、`opportunity`、`account`、`readerGoal`、`requiredQuestions`、`materials`、`form`、`webResearch`、`maxRevisions`；`standards` 默认从标准卡读取。`maxSeconds` 可选，仅表示真实硬上限。形式和时长建议不得默认为硬限制；不强迫每个题目有反直觉冲突。

`prior` 可带上一版 `draft` 与 `humanReview: { reviewer, notes }`。新的运行重新对照当前目的理解材料，不能沿用旧观众假设绕过目标变化。

| 角色 | 工作 | 主要资产 |
| --- | --- | --- |
| 研究编辑 | 对照原目的与每个必答问题建立解释草图；需要时查一手来源；指出缺口 | `content-research` |
| 作者 | 同时形成可调整的内容决定和完整稿；用写作发现篇幅与解释问题 | `content-draft` |
| 冷读者 | 只读观众可见内容，复述并提出仍然不懂的问题 | `content-reader` |
| 事实核查 | 对照材料检查事实与推断，不替创作者改变主题 | `content-fact-check` |
| 主编 | 对照原目标、完整稿、读者疑问和证据统一判断，决定回到哪一步 | `content-review` |

研究、内容决定和完整稿都可修订；单次运行的每轮资产有独立引用及依赖关系。工作台把完整稿放在主位置，中间资产放在审计层。

## 回退与停止

- `rewrite`：证据和目的成立，改稿即可。
- `research`：必要解释缺证据，带稿件与具体缺口回研究。
- `reframe`：当前主线无法兑现原目的，重新组织问题与解释，仍受原目的约束。
- `pass`：各必答问题有稿内解释，事实与显式约束满足，交创作者审阅。
- `blocked`：现有条件下无法兑现，说明具体缺口。

`maxRevisions` 是首次完整稿之后的修订预算。用尽仍不通过，结果为 `not-converged`，保留完整稿供诊断，不生成“内容已成立”的假通过。缺失必答问题覆盖、事实问题或超出硬时长，都不能仅靠主编返回 pass 绕过。

## 给 B3 的交接

一次 `content` 接受从该 run 自己的最终稿、内容决定和研究生成一版 brief。B3 接收准确版本的稿件、核心问题、解释结构、账号与制作意见。旧 B1/B2 brief 仍可读，新流程不要求两个来源分别接受。

详见[作品档案与交接](../03-architecture/brief-and-handoff.md)。
