# 创作接入共享底座实施计划

本页记录 2026-10-03 本地工作台原型的已做工作，以及尚未完成的共享目标。目标与职责以共享 [产品](../../../vendor/agent-workflow/docs/product.md)、[架构](../../../vendor/agent-workflow/docs/architecture.md)和[路线图](../../../vendor/agent-workflow/docs/harness-roadmap.md)为准。创作保留业务流程、角色、标准、作品档案和展示扩展；通用执行、评价、历史和工作台由 agent-workflow 提供。当前阶段不建设临时 VM。

## 已有本地原型

- `apps/workbench/`、`src/workbench/` 建立案例、冻结输入和配置、排队串行执行现有 `creation.content`／`creation.b3`，提供作品阅读、四问、比较、采用、故障查看与恢复入口。它使用 SQLite 控制记录、原生 workflow 账本和私有文件／trace；Agent 由 Codex 执行。
- 用户评价与受限 Agent A 评价分开记录；四问绑定确切资产和哈希。评价不自动采用；通过内容关口后才形成给 B3 的作品档案。Agent A API 有委托范围，但没有自动调度或校准评价器。
- 已有单机服务、环境、备份恢复示例；没有目标云服务器部署。旧文章入口、CLI 和私有历史继续可读，未自动迁移。具体操作见[本地原型使用与运行](03-architecture/business-workbench.md)。

2026-10-03 的原型验收记录为 creation 119 项测试、类型检查、两套页面构建以及 44 页文档链接构建通过；隔离浏览器案例用替身 Agent 走通两轮流程定义、评价、比较和采用，并检查 1440px 与 390px 页面。这是当时的工程证据，不能证明真实模型的创作质量、远程运行或共享目标完成。

2026-10-04 新增独立的 PG Space 接入，使用共享 schema 注册、节点能力、事务提交和控制台；[命令与边界](README.md#postgresql-space-接入)单独记录。确定性案例走通现有 CONTENT、模拟人工接受、作品档案、独立 B3 方案附件、反馈后的第二版及四问比较。额外回归覆盖同一运行内返工、重复审阅文字和准确轮次来源。数据库实际重启后，在空工作目录的新进程中读回正文、会话、上下文、知识、交接、比较与附件，哈希一致。该接入没有替换或自动迁移原 SQLite 工作台；完整 B3 制作、一般 Agents SDK 与真实内容质量仍未验收。

## 目标缺口与顺序

### 2026-10-05 当前交付：先完成单条 CONTENT

用户将本轮范围收敛到现有 CONTENT（原 B1+B2 合并的内容工作流）。保留它的研究、写稿、冷读、核查与编辑方法，接通共享存储和真实执行；B3、多 workflow 组合与跨空间组织留待后续讨论。

- [x] 核对上轮完成范围：共享 PG Space 与确定性 CONTENT 接入完成；订阅实跑仅验证合成材料探针。
- [x] 适配 CONTENT 的角色指令和输出 schema 到订阅 Responses 执行器，保留真实上下文及受限工具记录。
- [x] 基于共享 Space 服务提供案例、真实执行、准确稿件四问、指定基线反馈再跑与比较；评价和人工接受分开。
- [x] 提供操作者 CLI：读取 run／准确资产／上下文／session；`revise` 使用准确旧稿和反馈，`experiment` 固定原始材料用当前方法重新运行，记录版本、基线和假设。
- [x] 通过通用交互控制台提供上述操作，creation 只配置业务表单、流程和阅读器；保留原只读 API。
- [x] 完成权限／来源／重试回归、浏览器路径检查，以及一轮真实 CONTENT 运行和 PG 读回；内容质量未通过，单独记录如下。

迭代由人或受托 Agent 阅读证据、判断原因并修改方法，再通过 CLI 驱动下一轮；当前交付不包含自动调优器。2026-10-05 的 Node 24 验证：creation 128 项测试、共享 core／Space／合同／订阅适配相关 75 项测试通过，含真实 PostgreSQL 测试。并发重复命令只启动一次；评价、比较和迭代记录可重试；反馈再跑与方法实验的候选评价关联确切基线。工程检查不代替真实内容质量验收。

2026-10-05 MiMo 实跑使用历史冻结材料，按用户选择关闭新增联网研究，保留原始输入；订阅执行模型为 `gpt-6-astra / low`。一个 CONTENT run 产生研究、三版稿件和三轮冷读／核查／编辑意见，最终为 `needs_review / not-converged`。最后一版事实核查未提出问题，主编仍认为“评分如何成为参数调整、多轮训练怎样形成能力”的解释不足；这属于本轮模型评价，尚无创作者四问或人工接受，不能据此宣称 workflow 质量成熟。

实跑暴露两个不同问题：第三次写稿收到无具体代码的 provider SSE error；显式恢复成功后，发布错误地把旧失败作者上下文也计入来源候选。后者已修复为精确匹配成功步骤／尝试、输入、配置与输出。核实无任何提交效果后，仅将悬挂的那次发布显式协调为失败，再续跑；原失败历史、恢复原因及前后补丁均留在 PG 事件中，成功写稿结果得到复用。适配器随后补充脱敏的 provider 错误代码记录，供以后诊断；不能用新诊断能力倒推本次 SSE 错误原因。恢复目前需要操作者核对现场，不是通用的一键自动恢复。

补丁后，Node 24 的 creation 类型检查及真实 PostgreSQL 的三项接入回归通过；SDK 诊断七项、operator 查询四项检查通过。浏览器验证最终稿可读、只有准确的最终稿提供四问入口、390px 页面无横向溢出。CLI 从 PG 读回稿件和恢复事件。当前仅为本机入口，没有云端或手机远程访问验收。

本轮验收不把模型主编通过当成用户满意，也不自动替用户接受稿件。当前订阅执行器没有网页检索工具；首次接入只支持显式提供材料，联网请求须明确拒绝，不能静默降级。生产部署、通用 Agents SDK、自动发布和 B3 媒体执行不计入本轮完成范围。

| 顺序 | 应完成的交付 | 验收重点 |
| --- | --- | --- |
| 1. 共享底座 | 在 agent-workflow 明确并实现通用执行与版本、资产／评价／采用、Agent A、PostgreSQL 主存储、一般 Agent SDK 和 Codex 适配、工具／上下文、trace／session、通用工作台与恢复合同 | 已新增 postgres、space-contracts、spaces、agent-sdk（SIWC Responses）包；后者不是一般 Agents SDK。迁移前仍须核对数据、权限和恢复语义，见[当前实现](../../../vendor/agent-workflow/docs/space-storage.md) |

| 3. 真实业务验证 | 在固定输入上运行真实内容和制作，记录作品质量、四问、成本及失败；用创作者好坏正反例校准审阅者 | 工程通过与内容质量分别结论；未校准前不撤人审；Linux 制作链、模型权限及目标环境须实测 |
| 4. 服务交付 | 在明确服务器和授权后部署、备份、恢复及跨设备验证 | 运行、存储、权限、恢复、域名／HTTPS 和费用有实测记录；不因本地页面可开而宣称上线 |

共享层完成之前，可以继续用本地原型验证创作业务，但新通用能力应在 agent-workflow 落地，再由创作消费。选中的历史资产按确切来源导入；不要自动改写旧数据库或复制私人 trace、媒体、凭证。恢复旧 run 需核对当时输入、定义和环境，不匹配时保留证据并新建候选。

一份作品被采用不代表流程在其他案例可靠。正式流程版本的采用需要代表案例与未参与调优案例；进一步减少创作者参与还需要正反例校准。创作代码、文档和共享库的检查应分别执行，构建结果不能代替业务质量判断。
