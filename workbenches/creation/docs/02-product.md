# 产品：创作者怎么用它

**给谁用：** 一个竖屏短视频账号的创作者。他手里有一个选题机会（大家在关心什么、市面上缺什么）、账号定位、做过的参照作品和一些材料，想得到一条能发的视频，并且希望自己参与得越来越少。

**做什么：** 三个阶段依次把选题机会变成成片。每个阶段由 workflow 里的 Agent 完成，结束时交给创作者一份主资产和一个判决建议；创作者判“通过 / 要改 / 作废”，通过后自动生成交给下一阶段的作品档案。

## 每个阶段，创作者给什么、拿到什么

| 阶段 | 创作者给 | 拿到的主资产 | 创作者要判断 | 这一篇里需要人的次数 |
| --- | --- | --- | --- | --- |
| B1 定题 | 选题机会、账号定位与现状、参照作品及教训、材料、载体（如竖屏 90–120 秒） | 内容决定：核心问题、一句话答案、钩子、3–5 个节拍、不讲什么、考虑过但没选的答案 | 问题选得对不对，答案站不站得住 | 调优前 1 次；b1-v6 起盲跑不需要 |
| B2 成稿 | （来自作品档案） | 完整稿：标题、封面字、每段口播 / 屏幕字 / 画面意图 | 观众跟不跟得上，事实有没有错 | 2 次审阅意见 |
| B3 成片 | 配音方式、样片还是全片 | 样片或全片视频、封面、每段快照 | 声画是否讲出了稿子，手机上看不看得清 | 2 次审阅意见 |

所有介入都是审阅意见，没有一次由人或主 Agent 代写。“要改”时写下具体意见（B3 按段落写），workflow 带着意见重跑；意见会写回这个阶段的标准卡。

## 在哪里看

| 页面 | 生成命令 | 看什么 |
| --- | --- | --- |
| 作品工作台 | `pnpm stage:workbench <topic>` | 一页看全：三个阶段各一行（当前版本、主资产、判决、进度），下面是作品档案和全部调优历史 |
| 阶段页面 | `pnpm stage:render <topic> [runId]` | 一次运行：这一阶段的决定 → 审阅者与创作者的判决对照 → 为什么是这些角色 → 每个角色的进度 → 输入 → 全部产出（B3 内嵌视频） |
| 交接全图 | [作品档案与交接](03-architecture/brief-and-handoff.md) | 每个角色拿到什么、产出什么，哪些是故意不给的 |

页面是生成的静态 HTML，在本机用任意静态服务器打开 `.local/stages/<topic>/index.html`。

## 给创作者看什么，不给什么

| 直接展示 | 展开才看（审计层） | 不展示 |
| --- | --- | --- |
| 每个阶段的主资产，结论先行 | 审阅角色逐条判定、冷读者的复述、事实核查清单 | 原始 prompt、事件流、Codex 会话文件 |
| 判决与一句理由；创作者自己的意见 | 中间草稿与每轮修订 | 本机路径、凭据 |
| 这一版改自哪次审阅 | 调用耗时、token、失败命令（`stage:trace`） | |
| 作品档案里“留给下一阶段的话” | | |

## 两条产品线的关系

| | 阶段 workflow（本文档主线） | 文章应用 |
| --- | --- | --- |
| 做什么 | 竖屏视频：B1 定题 → B2 成稿 → B3 成片 | 文章：内容定义 → 完整文章 → 独立复核与有限修订 |
| 入口 | 命令行 + 生成的静态页面 | 网页（API 4337）+ 独立 worker |
| 代码 | `src/stages/`、`scripts/` | `apps/`、`src/application`、`src/workflows/article.ts` |
| 状态 | 在一个真实题目上调优到可用 | 2026-09-29 首版，真实 SDK 首稿跑通，方法未调优 |

两条线共用 agent-workflow，但目前各自独立。把阶段 workflow 接进网页工作台，是等阶段 workflow 在更多题目上稳定之后的事。文章应用的接口见[文章应用合同](03-architecture/article-app.md)。

## 还没有的

- **发布（C1）与发布后数据回流（C2）：** 发布后互动与复盘的协议已写好（见[发布后](04-workflows/after-publish.md)），但还没接进这套 workflow；数据也还不能回流到下一篇的 B1。
- **正式配音：** 需要创作者配置 MiniMax 密钥与声音，目前成片用占位配音。
- **换题验证：** 所有调优都在一个题目上，下一步用新题从 B1 盲跑到 B3。
