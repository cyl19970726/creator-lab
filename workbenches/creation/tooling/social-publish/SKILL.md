# 三平台视频发布

先读 README.md，使用同目录 publish 工具。浏览器交互遵循 ego-browser skill。

## 五步执行

按 [README](README.md) 完成：发布包准备 → 封面按比例导出 → 三平台填写与上传 → 预览核对 → 提交及回执。

- 本地 `pack/check/covers` 批量处理可重复机械工作；浏览器使用当前 ego TaskSpace/Page API。
- `prepare` 不提交，`preview/review` 记录执行者实际看过的当前版本；用户既有授权有效，不重复问发布许可。
- 封面导出待视觉核对，未提供横版设计时 contain 只是保底版；布局在内容设计与样片阶段解决。
- 遇到平台控件变化，先 inspect 读当前页并校准 job.adapters，保存阶段与证据，不循环上传。
- `submit` 点击前写入项目级账本；结果不明确只 verify，不能改任务名、题名或重编码绕过未决提交。
- 本期已提交视频仅做回执与防重验证，不用于真实重复发表。
- 各平台适配的校准状态写在 adapters.json。模拟页面通过不等于三平台实发通过。

## 立即与定时

用户授权发布后可直接执行，无须额外确认发布权限。账号、发布平台、素材和时间必须确定；身份不符或未登录时请用户切换登录。

- 第一条马上、第二条两小时后：以收到指令的当前时间计算一次第二条绝对时间，按分钟保存。不要在每个平台上传或重试时重新计算两小时。
- 配置 `publication: {"mode":"immediate"}` 或 `publication: {"mode":"scheduled","at":"2026-09-08T00:00:00+08:00"}`。平台配置可覆盖全局设置。
- 时间使用显式时区。此工具在网页中填写北京时间，跨日须明确日期。
- 使用平台原生定时发布，不用等待两小时再点击、操作系统任务或线程提醒代替。
- 定时已过、平台不接受该时间、控件回读不一致时停止该条提交；不得改成立即发布，不得擅自顺延。

## 执行和验收

1. check 检查视频、封面、文案、账号及时间；probe 核对真实账号名称和唯一 ID。
2. prepare 上传并填写，保存实际封面预览。AI 内容声明开启，原创按用户要求填写。
3. preview 生成当前视频新帧与设置证据，由执行者实际核对后用 review 记录；不重复索要已有发布授权。对当前页面校准 `adapters.PLATFORM.publication`（见 README）。立即模式也要回读其选中状态，避免继承上次定时设置。
4. submit 再检查选中模式、完整日期和时间、账号与文案，然后只提交一次。
5. verify 在该作品对应的列表项核对定时状态和准确日期时间；仅有标题、上传完成或提交按钮消失不足以证明预约成功。
6. 保留截图、实际定时时间和作品标识。区分“已提交审核”“定时待发布”和“已公开发布”。

当前状态：定时配置、字段填写回读、防过期、防重复和预约证据验证已有离线测试。三平台真实控件适配必须用登录后的页面校准；尚未完成本次三平台定时发布端到端验收。不能将离线测试通过称为发布成功。

## 2026-09-07 现场操作补充

- 浏览器 Profile 3 是 Token经济猫，Default 是 hhh-01，彼此隔离。使用对应既有空间，不假设新空间继承所需 profile；页面还要核对网站唯一账号ID。
- 抖音定时输入是 `input[placeholder="日期和时间"]`，使用真实键盘输入并 Enter，再失焦回读。普通填充可能无效。最少2小时、最多14天；不足提前量需用户指定新时间。
- 小红书定时开关开启后，输入日期时间并失焦回读；已验证 `2026-09-08 02:00`。作品列表需同时出现该标题、定时发布和时间。账号限制拒绝后，只有用户确认限制解除、列表确认没有该预约，才可重试。
- 视频号描述框是 `.input-editor[contenteditable]`（属性值为空）。定时单选为 `input[type=radio][value="1"]`，立即为value=0。时间总字段 `input[placeholder="请选择发表时间"]` 为只读，应通过日期时间选择器设置，不移除readonly。当前值恰好符合用户时间也要回读；这次默认02:00符合已确认计划，未修改DOM值。列表回执是“将于2026年09月08日 02:00发表”。
- 视频号上传曾停0%，未提交前取消并重新上传后恢复。上传完成、转码结束后才编辑封面。
- 这次三平台定时均由浏览器现场完成；不据此宣称旧通用脚本的所有封面弹窗适配已端到端通过。
