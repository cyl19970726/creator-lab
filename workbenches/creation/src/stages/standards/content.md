# Content 内容验收卡 v2

一次内容迭代同时交付内容决定和完整稿，创作者只在终点验收一次。原始 opportunity、readerGoal、requiredQuestions 是每轮的目标；研究材料、旧稿、模型自拟的观众直觉均不得悄悄改写目标。标准用于主编审稿，也用于判断是否回研究编辑补证或重定主线。

- C1 阅读目标：完整稿让目标观众真正学会 `readerGoal`，不是只提出一个有吸引力的问题。
- C2 必答问题：逐项写出 `requiredQuestions` 在稿中的具体答案。任一问题没有讲明白，不能通过。
- C3 内容决定与全文一致：核心问题、一句话答案、节拍和最终口播互相兑现；可在同一轮一起改。
- C4 证据与边界：事实可以由所列材料支撑；看板、发布后总结、独立验证各有边界。研究缺口不可伪装成答案。
- C5 冷读：只看标题、封面和稿件的读者能用自己的话复述关键机制与结论；跟丢处及与阅读目标相关的未解疑问要定位；不把复述术语当作理解机制，也不要求满足主题外的所有好奇。
- C6 事实：明显错误、无来源或过度推断必须修改。事实核查的 issues 尚未解决，不能通过。
- C7 表达：顺序服务理解，画面意图帮助观众看懂；不强制固定段数、套路式反转或等长替换。
- C8 时长：只有输入显式指定 `maxSeconds` 才是硬上限；否则根据学习目标安排所需篇幅。

主编可选择 rewrite（改稿）、research（补证）、reframe（重新确定内容主线）或 blocked；每次回退须保留全文、评审和原目标。预算耗尽时交创作者审阅，标明未收敛，不得伪称通过。

运行时校验会独立复核 C1–C8 是否逐项给出、必答问题是否逐字对应并得到具体答案、事实问题是否清零、显式时长是否合规，以及稿件和研究中的来源 ID 是否存在且不冲突。程序拒绝通过时，原因记录为 `guardFailures` 并传到下一轮；研究来源 ID 与原材料或不同 URL 冲突时明确阻断。本版是 v2 的运行合同修复，不能归作此前 v1 实跑的质量结果。
