# B2 标准卡 v1

B2 只做一件事：**让 B1 定下的答案被观众跟上，并愿意看完。**
主编逐条检查；每条给 ok / weak / fail 和一句理由。**T1、T3、T5、T6 是硬标准**，任何一条 fail 即 revise；T2、T4、T7、T8 是改进项，只有冷读者在同一段连续两轮跟丢且影响复述时才阻止通过。

| id | 标准 | fail 的样子 |
|---|---|---|
| T1 | **前 3 秒就是矛盾。** 开口第一句抛出观众的疑问或反直觉事实，与 B1 的钩子一致。 | 开头是"今天我们来聊…"、背景介绍、免责声明。 |
| T2 | **一段只加一个新东西。** 术语第一次出现时立刻给白话；一段话不塞两个新概念。 | 一句话里出现 rollout、verifier、buffer 三个新词。 |
| T3 | **冷读者能复述答案。** 只看观众能看到的内容，就能说出那句一句话答案。 | 冷读者复述的是组件清单，或说不出结论。 |
| T4 | **核心机制有一个具体例子或类比。** 观众能用这个例子向别人转述。 | 只有抽象描述，没有一个能记住的画面。 |
| T5 | **没有错，也不过头；限定最多两处。** | 事实错误；或为了严谨每段都挂免责。 |
| T6 | **时长守预算。** 默认 ≤120 秒，口播约每秒 4 字。修订不能只加不减。 | 越改越长；新增内容没有替换掉旧内容。 |
| T7 | **每段一个主画面，画面服务理解。** 画面意图能做出来，并且在手机上看得清。 | 画面堆满术语和箭头；或画面与口播无关。 |
| T8 | **结尾留一个可带走的判断，并连到账号视角。** | 结尾是总结复读，或"欢迎关注"。 |

### 2026-09-30 · Kimi/GLM「弱模型怎么训出强模型」· 代理审阅（Claude 代创作者）
主编连续 4 版判 revise，39–82 秒一直被冷读者跟丢。审阅结论：**局部修补修不好结构问题**。
1. 同一处连续两轮没修好，就改结构：每个案例只出现一次、只承担一件事（本题：Kimi＝长任务怎么判；GLM＝判完怎么变强）。
2. 一张贯穿图不能在后面反复出现；每段一个主画面。

4. 审阅者给的修改同样要核事实：代理审阅要求补的"让任务现场一直开着"与 Kimi K3 §5.3.2 相反（暂停的沙箱等待推理时不占 CPU 和内存），被改后核查拦下，按原文更正后通过。
5. 结论：第 7 版结构通过；两处修改后（事实 + 账号视角）事实核查 0 问题，B2 接受，进入 B3。
