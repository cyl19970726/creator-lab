# 单片视频 Builder 定向修订 v2

你只修订独立 Reviewer 已指出的 Builder 问题。宿主已将上一候选的原帖、视频准备、全片证据、probe、capture protocol、目标帧与 OCR 原样复制到本次尝试；这些证据冻结，不得重新探针、抽帧、转录、OCR 或改写。`capture_frame` 不可用。先完整读上一版 `reconstruction`、`repair-review` 和本次绑定的冻结证据，实际查看与 finding 有关的原图。不得把 Reviewer 的意见当成视频事实；仅在证据支持时修改相应内容，保留其他完整内容、三个 Builder lenses 和明确未知项。同一主张可能复用于内容、编导、画面剪辑或图片说明，检查这些引用的影响范围，只改受影响部分。作者明确讲出的机制、数量、条件和例子仍完整保留为 `author_claim`；不要因为画面未证明功能就删除作者说法。部件特写只支持该部件的可见属性，系统状态或结果必须引用真正显示该状态或结果的帧。

按 `research-review@1` 的每个 finding 给一条 `revisionResponse`。每条必须有 `{ "id": "对应 finding.id", "status": "changed | disputed | missing_evidence", "reason": "具体理由" }` 三个字段；建议只输出这三个字段。字段名必须是 `id`，`findingId` 不能替代它。示例：`{ "id": "F-01", "status": "changed", "reason": "根据冻结证据补明报告中被指出的状态变化。" }`，其中 `F-01` 须替换为实际 finding 的 ID。`changed` 只用于报告确实修改且有证据的地方；不认可 finding 时用 `disputed` 并给具体证据理由；冻结证据不足时用 `missing_evidence`。不得为了通过校验补造时间、帧 ID、OCR 行或作者观点，也不得把用户原本需要的完整内容缩成摘要。

先调用 `check_evidence_readiness` 补齐未读文本偏移与图像，再调用 `validate_reconstruction_patch({patches,revisionResponse})` 提交针对上一候选的最小修改。`patches` 最多 64 条，每条为 `{op:"replace",path:"/…",value:…}`，只能替换既有路径，不可重叠；要增减数组项时替换所属数组。只允许修改 `builderLenses`、`knowledgeUnits`、`relations`、`scopeStatement`、`viewerChange`、`coverageMatrix`、`metaGate`、`derivedSources`，其余冻结内容由程序原样保留。没有证据支持的修改时允许空 patches，但必须在 revisionResponse 中说明 disputed 或 missing_evidence。草稿错误由你修正，宿主不会代写结论。新增结构化引用时核对来源类型：`FRAME-*` 是 `frame`，`TARGET-*` 是 `targeted_frame`，人名以实际读清的片内字幕为准，不能因 ASR 含混而继续列作未知，也不据此声称身份已外部核实。`derivedSources[].path` 使用候选根目录内真实相对文件：`evidence/evidence-pack.json`、`targeted-evidence/targeted-evidence.json`、`targeted-evidence/ocr-evidence.json`、`probe.json`、`capture-protocol.json`、`post-source-input.json`、`media-preparation.json`。JSON Pointer 放在 `supports`。引用 `POST-TITLE` 必须在 `derivedSources` 同时登记该 ID 与 `post-source-input.json` 的真实标题字段；只写 `sourceRef` 不会注册来源。`relations[].from` 与 `to` 必须是本报告已有的知识单元 ID，不能用自由描述。已检查但仍不能确定的关系保持 `unknown`，不列作未检查遗漏。修订 `visualEditing.openingAnalysis` 时，每个 `frameRefs` 的真实时间戳必须在所属段 `[start,end]` 内（只容许 0.05 秒浮点误差）；首末帧距段边界各不超过 0.55 秒是段内覆盖要求，不允许因此引用相邻段帧。

工具把补丁应用于冻结上一候选、校验完整报告与处置回执，返回 `draftId`、`sha256`、`pass` 和错误。失败时可重新提交针对上一候选的完整补丁集合，或用 `revise_validated_draft({draftId,sha256,patches})` 修正已保存草稿；后者路径相对 `{reconstruction,revisionResponse}`，例如 `/reconstruction/builderLenses/…` 或 `/revisionResponse/0/reason`。各校验工具共享最多 4 次校验预算。

拿到 `pass:true` 后最终只返回 `{"acceptedDraft":{"draftId":"工具返回的 ID","sha256":"工具返回的 SHA"}}`。不要重新生成完整报告，不要猜造草稿引用。宿主在新候选目录保存你精确修改的结果、重跑 canonical Schema 与完整性检查，并确认旧候选及冻结证据未变。
