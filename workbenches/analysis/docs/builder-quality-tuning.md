# 单帖 Builder 内容质量调优

单帖主报告来自 `reconstruction.json.builderLenses`。质量验收直接读完整的内容还原、编导逻辑、视觉剪辑三个视角，并回到原片材料核对。字段合法、运行成功、Reviewer 没有意见都不能替代成品质量判断。Reviewer 调优的独立约束见 [审阅调优](reviewer-tuning.md)。

两轮 Builder 的第二轮是新会话。即使第一轮已经检查过开头和封面，第二轮仍须重新检查已绑定的 `opening-contact` 与 `post-cover`；宿主的就绪检查和最终校验都检查本轮的读取记录。探针文字不能替代正文作者实际看图。这项要求解决证据缺读，不代表分析深度已经过关。

当前 Builder 提示词 v4.13、Reviewer v13、修订 v4 仍处于实验验收。提示词版本与实验批次编号分别记录。此前 v4 同片候选虽通过 schema，却出现主文断段和开场画面错位，未被采用。v4.1 第一次运行因授权接口返回 401 未产出最终候选；诊断确认长调用沿用了已经过期的 SIWC token，共享 SDK 已改为每次请求检查授权，并在 401 后最多刷新重试一次。

修复后的 v4.1 完整同片流程成功，但人工审读仍发现主文漏掉画面独有的机制关系、将可读字幕保留为未知，以及中后段剪辑分析范围过宽。v4.2 因此改为以三个主视角为写作中心，检查跨载体新增信息，并分析真实局部切镜或画面延续。就绪工具按捕捉问题显示本轮已看/未看原帧及时间；`ready` 只表示最低读取条件，`semanticCoverage` 始终不作自动判定。授权、程序和内容质量是独立验收，不要自动替换已有报告。

v4.2 完整运行再次成功，但主文缩成主题提要，中后段剪辑分析退步，Reviewer 零问题仍漏检。原始 trace 证实模型正常完成输出且已使用新版读取工具，没有输出上限截断。该版本未获质量接受。更多读图或更长提示词都不自动保证成品深度。

v4.3 改变第二轮内部的写作方式：Builder 在同一 Agent 会话中按需读取每个视角的 schema，分别写作、暂存三篇完整正文，再提交证据索引和三个精确草稿引用。宿主只原样组合 Builder 的文字并运行原有完整校验，不补写结论；报告格式、两个 Builder 轮次及工作流节点不变。这是集中每次写作目标的实验，不是已经证实的质量提升，也不承诺省 tokens。必须重新比较正文、引用、耗时和输入输出量。 首次实际试验成功暂存三个视角，但整合时因图解段落缺少图像声明、开头时间范围不一致而失败，没有最终候选。中间草稿相对上一版恢复了主线与部分编导解释，仍遗漏画面独有机制并混淆局部切镜；不能据暂存成功宣称整体提升。

最终带局部反馈的同片完整运行成功，耗时29分41.906秒、35次请求；Reviewer仍返回零问题，未触发修订。独立全文和原帧审阅确认：编导因果与适用条件解释有局部增益，但主文丢失旧版已保留的画面信息，开头字幕时序错误，中后段转场说明仍跨过多个切镜而未解释具体选择。因此v4.3仍未获质量晋升，也未实现提速。实际调用先读取了三个视角的schema再写作；当前暂存方式不隔离视角上下文，不能将设计意图视为已发生的行为或已证实的质量收益。最后候选可读不等于成熟流水线，原选择未替换。

## v4.4：切镜证据与固定上下文

这一轮保持两轮 Builder 与 `post.analyze@v11` 的业务节点不变。每轮用 `read_builder_context` 一次交付必读源文和实际图像，第二轮同时提供三个视角和索引 schema。JSON 仅去除字符串外的格式空白，保留数值字面量和字符串内容；来源哈希、完整读取记录和原有最终校验继续生效。超出批量边界时明确返回分页补读要求，不把截断内容记作全文已读。

证据包增加检测切点前后原帧及接触表，引用仍落到具体 `FRAME-CUT-*`。检测候选不等于完整真实切镜表；界面变化、镜内运动和相似画面的切换可能漏检。提示词要求逐处确认实际出画与入画，在局部窗口内解释新增信息、台词分工、继续留画的代价和借鉴条件，并检查没有换镜但话语推进的段落。

验证使用同一条143秒基准片与三条不同材料：49秒软件界面讲解、124秒口播/产品插画新闻、23秒篮球现场。全部使用已保存原片，固定源文件与方法摘要，不向生成或修订模型提供人工核对笔记。v4.4完整同片实际耗时12分01.712秒、28次请求，比上一轮29分41.906秒减少59.5%。但仍未达到十分钟工作目标；独立审读发现同期话语与切镜关系仍有错误、可读文字被ASR带偏，并有分析退回清单的问题，因此不自动替换原报告。

## v4.5：局部修正保留完整分析

v4.4的剪辑视角因开头帧引用和时间覆盖问题被暂存拒绝两次。模型整篇重写用了约150秒，并将相关调用参数从11,917字符缩至8,353字符；缩短的部分包括原有替代选择解释。暂存失败不应强迫模型重新输出整篇。

`revise_builder_lens`现在接收指定slot的最新draftId/sha256和最多64条replace补丁，原样保留未修改字段，并重新执行同一校验。失败的新回执仍可继续局部修，旧回执或跨视角引用拒绝；缺失字段需替换最近已存在的父对象。最终完整报告校验继续执行，宿主不添加分析。提示词和运行时指令均指向局部修正，避免矛盾地要求全文重交。

本轮另修两项边界：批量图片在记录已读取之前检查SDK单图传输上限；最终转写来源标记由冻结证据提供，不能被模型占位文字覆盖。四条样本在这些修改冻结后重新进行完整流程验证。结果记录区分SDK错误、视角暂存拒绝、局部修订和完整报告校验；不得将“没有SDK错误”表述为“完全没有被退回过”。

v4.5完整基准片实际耗时15分16.485秒、30次请求；23秒体育片耗时9分25.074秒、22次请求。局部补丁已实际替代整篇重写，具体切镜的替代选择与借鉴条件更完整，但原片仍有ASR错词、同期字幕时序和引用画面错位；体育片遗漏一处结果字幕，不能算完整内容通过。软件片在第二轮写作中出现`terminated`，新闻片在第一轮出现`fetch failed`，两条都没有最终报告，失败记录必须保留。

基准片较v4.4变慢的主要可观测差异是索引调用增至34,279参数字符、约242秒，其中约12,000字符在重复不可修改的冻结转写。不能把API等待全部称作生成时间；它还包含网络、排队和流读取。

## v4.6：源文字核对、精简索引与传输恢复

Builder只输出自行判断的正文和索引，冻结transcript从已校验指纹的evidence-pack投影，在草稿schema校验之前注入。最终报告格式及完整校验不变，语义性的cueAccountability仍由Builder保留。

存疑专名、材料、数字与工具文字使用协议内的OCR/UI动作和短时间窗；自动采样受每动作60帧、总计180帧约束。本地Vision只读取明确请求的文字帧，引用缺失明确报错。OCR是待核对的文字提案，不能替代原图；实际两帧冒烟测试约1.6秒，不能据此推断所有视频的OCR时间或质量。切点证据旁同时提供冻结ASR在前后采样时刻仍在进行的句子及下一句，保留字幕/声音时间不完全等同于ASR的边界。

共享官方Agents SDK适配器对同一未完成模型turn的可识别连接错误最多重试一次，不重放已完成工具；SSE失败及工作流取消不作传输重试；后续版本已把可恢复HTTP服务端错误纳入同一重试预算，401授权刷新仍有独立上限。错误事件保存脱敏的阶段、错误类别、请求编号和已读字节，避免只剩`fetch failed`。这提高可诊断性与局部恢复能力，不保证外部服务始终可用，也不自动重跑失败的完整工作流。

本版仍须重新完成同片与跨题材验收，不能把实现或单元测试作为速度/质量已经改善的证据。

v4.6的四片验证中，软件片完整结束，用时11分55.735秒、29次请求（该轮新增帖子最多两条并发，不能直接当作独占资源的基准时间）。独立审阅认为主线和剪辑解释有实质价值，浏览器、框架迁移、渲染器三个例子分开，25倍性能仍作为作者主张；一处界面任务名称与旁白关系尚未说透。基准片保留了更准确的三篇正文草稿，但索引有一个未登记来源引用待修时收到HTTP507；体育片也在第一轮收到507。新闻片因模型协议规划187个唯一时间点、超出180上限而失败。三条失败都不能计作完成，草稿质量改善也不能换算为完整流程提速。

后续工程修正把同一个补帧计划器用于方案校验和实际抽帧，在方案提交时返回总数、超限动作与范围，保留原上限和模型取证选择。SDK的服务端重试与连接重试共用一个预算，重试同一尚未完成的模型请求；它不能证明507根因已经消失。Builder仅在经过原有完整校验的通过回执之后，由官方SDK结束本轮，省去模型重复回传回执的调用；失败回执仍须模型修正，宿主不能自行改写正文或跳过验证。修正效果待新的完整实片运行确认。

## 断网后的执行器与修订改进

实际运行遇到连接中断和域名解析失败，用户随后确认当时网络断开。这些失败保留在运行历史中，不算完整流程耗时或质量通过，也未因此修改全局代理或授权。

共享 SDK 现在记录响应头到达和每隔至少15秒的流接收进度（字节数、事件数，不记录秘密或流正文）。等待响应头或连续没有新数据默认上限为180秒，持续传入的数据重置空闲计时；同一未完成请求的恢复仍共用一次预算。工作流总时限与独立校验仍保留。这些措施使长时间生成与断连可区分，不代表网络中断已经被软件消除。

Builder 草稿的局部修订允许模型添加缺失的对象属性，前提是父对象存在；不能覆盖已有属性、向数组插入、修改冻结字段或绕过原有整稿校验。旧有报告修复路径仍保持只替换已有字段。这样可以修复必填字段遗漏，而不要求模型为了补一个属性重写整份索引。

Builder v4.8 与 Reviewer v9 额外核对摘要和正文的部件关系是否一致、画内文字首次出现与延续的区别、以及“界面”描述是否真有对应像素。具体字幕、时间或本次评语不作为生成答案输入。新版本的质量与速度必须用后续完整实跑确认。

## v4.9 验证与下一轮修正

该次完整同片运行用时9分21.876秒、21次请求，相对29分41.906秒减少68.5%；这是同一冻结本地媒体的一次观察，不能代表平均或尾延迟，亦不包含下载。体育片完整运行8分37.734秒、23次请求。独立质量审阅确认剪辑视角已能解释具体切镜的内容增量、留镜代价和复用条件，但原片正文仍有字幕首现时刻、材料词和主图引用问题；体育片仍有配图错位与动作遗漏。两者Reviewer均零问题，不能据此自动采用。

新闻片运行12分48.635秒后失败。原始工具参数核对发现模型分别抄错了一位草稿编号和一位SHA字符，严格宿主校验正确拒绝；模型在技术纠错后重写已完成视角，把全片正文缩为开头提纲。不是宿主错误解析最新回执，也不能把缩水归因于Schema。

下一轮把当前草稿选择交给明确的工具参数：`useLatest:true`修订某一视角，`useLatestBuilderLenses:true`组装索引。宿主仍核验每个当前草稿的实际ID、SHA与通过状态，不回退旧通过稿，不改写正文；不能同时传入显式回执。上下文与纠错反馈列出现存草稿，提示保留已完成文章。局部`add`只允许在已存在对象内补缺失属性，不可覆盖或插入数组。

内容块主图的冻结时刻与块范围不一致会在暂存和最终完整性校验中报出精确位置；显式before/after对照与一般evidenceRefs保留跨时间比较用途。`inspect_evidence_window`按短窗口一次交付所有已登记原始帧和TARGET帧及顺序标签，防止只看TARGET两端而漏掉已有DENSE中间帧。超出图片/传输边界时返回拆窗要求，未交付不记为已看。Reviewer补齐OCR全文与开头序列读取；读取完成仍不是语义质量判断。这些改动需再次实片验收。

## 成品标准

| 视角 | 读者应当得到什么 | 不足的表现 |
| --- | --- | --- |
| 内容还原 | 连续理解原片的机制、条件、过程、转折、具体参数与结论；区分作者主张和观察 | 只有主题摘要；具体关系仅留在知识单元或其他视角；自行补造原片没有解释的机理 |
| 编导逻辑 | 由具体台词、画面及其先后关系，理解问题如何提出、回应和转变；解释选择的作用及适用条件 | 把主题分别换词填入功能、认知变化、回报；把合理解读当作已测得的观看效果 |
| 视觉剪辑 | 在重要转折处定位前后画面及台词，理解画面、文字和口播怎样分工，哪些素材使表达成立 | 用几十秒的主题概述冒充镜头分析；只有快慢标签；从字幕推断未看过的动作 |

分析深度不等于字数。检查新增段落是否增加了有来源支撑的理解，而不是重复事实、术语或可靠性提示。无法语义读取音频时，保留音乐、音效和声音节奏的缺口，不以转写代替完整视听分析。

## 同素材只重建 Builder

Node 24，沿用分析工作台的 PostgreSQL 与现有 SIWC 配置：

```sh
corepack pnpm --dir workbenches/analysis exec tsx scripts/benchmark-post-builder.ts \
  --source-workflow-run-id HISTORICAL_WORKFLOW_RUN_ID \
  --case builder-quality --dry-run
```

先核对 dry-run 的源候选、冻结文件、新提示词与 skill 摘要，确认本地视频可用。多个候选时用 `--candidate-artifact-id` 明确选择。隔离 checkout 使用自身的 `SELF_MEDIA_PROJECT_ROOT`，并将 `SELF_MEDIA_RUNTIME_DIR` 指向原冻结媒体所在目录；可用 `DOTENV_CONFIG_PATH` 引用已有配置，无需复制凭证。

删除 `--dry-run` 后使用 `gpt-6-luna`、medium 和正式 `post.build` 两轮流程，重新生成探针、目标证据和 Builder 正文。输入强制 rebuild，不复用旧正文；历史冻结文件的路径和 SHA 必须保持一致。旧候选和人工评语不作为 Builder 的答案示例。宿主执行原有 schema、来源及完整性检查。

入口将新 trace 与候选分别写入 PostgreSQL 和私有 runtime，不调用 Reviewer、修订或注册，不改变当前页面选中的报告。`--output` 可指定新的私有结果文件；结果记录模型、方法版本、运行、候选、耗时、请求数和宿主校验。运行失败仍需查看 trace，不应计作质量通过。

## 同素材完整流程

```sh
corepack pnpm --dir workbenches/analysis exec tsx scripts/benchmark-post-workflow-run.ts \
  --source-workflow-run-id HISTORICAL_WORKFLOW_RUN_ID \
  --case full-quality --dry-run
```

核对 dry-run 后去掉 `--dry-run`，通过对比入口复用 `post.analyze@v11` 定义执行来源检查、两轮 Builder、独立 Reviewer，以及有修改意见时的一次修订。此入口使用 `full-post-benchmark@1` Agent 配置，不经过生产任务启动与当前版本登记入口。冻结输入、模型、授权和隔离目录要求与 Builder 入口相同。结果保留完整运行树的耗时、请求数、方法与 SDK 源码哈希，以及修订前后的候选和 review；不会注册候选为当前版本或改变 batch 选择。结果写入私有 runtime，失败记录也保留。

V11 的修订分支不会再次独立审阅修订稿，因此仍标 `revised_unverified`。无 findings 只表示本轮 Reviewer 没有提交问题。比较入口始终保留 `qualityAccepted:false`，需要另外完成正文及来源审计；不将空 findings、schema 通过或流程结束当作质量晋升依据。

## v4.10 验证与错误反馈修正

原片实验在10分52.207秒、24次请求后失败，三篇正文草稿仍保留；它们通过了局部结构校验，未形成完整报告。显式选择最新草稿生效，没有再手抄错回执。阻断来自知识单元把不同时间的OCR引用放在一个较短范围里，模型只迁就一个引用移动范围，又使其他引用越界。原来的反馈仅列引用编号；现在保留严格校验，同时给出真实范围、每条引用的冻结时刻和同单元其他带时间证据，由Builder修正语义范围、拆单元或删除不适用引用，宿主不自动改正文或扩范围。

独立草稿审阅确认：开头英文出现时刻、可读材料、软件界面措辞与主图范围问题得到改善，两个真实切镜有具体因果、留镜代价和素材条件。但独立部件机制与一段从原理到应用的衔接仍有遗漏，不能作为完整报告验收。提示词因此强调分别保留画内对象—作用—结果关系，以及主题之间实际存在的推导。

新闻实验在6分39.240秒、10次请求后因连接EPIPE、重试ENOTFOUND停止，无候选。此前补帧方案也未通过：某动作列出122个显式时刻、上限60，模型只改范围而未减少列表。补帧校验反馈需要明确实际采样来源和纠正方法；原上限、选帧责任和完整校验保持不变。当前接口连通恢复不等于网络稳定性已获证明。

## 对比与采用

独立读取旧版与新版全文，对每个视角记录具体改进、退步和对应原材料；特别核对新增加的机理、因果解释、人物关系、数字和镜头判断。主文遗漏不能因为其他字段有写而算作覆盖。引用正确与内容有洞察分别判定。

先做相同素材的可追溯比较，再用不同题材检验可迁移性。一次样本的改善不足以证明稳定质量或吞吐量。实验候选不自动获得独立审核通过状态，未经验证的提示词不能因为少报问题或文章更长而晋升。


## v4.11 观察与 v4.12 验证方向

v4.11 原片完成用时16分28.648秒、53次请求。独立阅读发现，部件机制和应用衔接已恢复，剪辑解释包含具体换镜信息、继续留镜的代价和借鉴条件；仍有材料字幕漏读和一处入镜文字时间错位，未做质量验收通过。第二轮24次单图调用分布在24轮；不能把这部分时间归于下载。

同版本新闻片10分44.679秒、24次请求后未产出集成候选，三篇暂存正文保留。真实封面存在且视觉解读基本准确，但正文使用图片路径及工具别名代替POST-COVER；模糊错误回执让模型反复修改索引仍未解决问题。内容还原的金额和平台关系较完整，视觉剪辑仍把一处任务不匹配的界面当成口播所述操作。

下一轮改动：

- `inspect_images` 一次交付最多24张独立已知原图，保留实际像素、精确身份和容量校验；批量交付不表示已理解。
- OCR合并所请求文字窗口内全部冻结原帧与相应TARGET；按512个唯一帧ID独立预检，不截断、不重新抽视频。保留多动作关联与原图时间；报告读图链接支持新的候选根路径。历史没有新路径标记的证据仍按旧路径读取。
- 标题/封面来源身份在DL暂存时局部检查，错误明确指出字段、规范来源ID和局部修订方法。宿主不代写分析，不放行兼容别名。

仍以新的完整运行和独立源片审阅判断结果。新增证据、通过Schema或Reviewer没有发现问题，都不是质量自动验收。

## v4.12 实测与 v4.13 综合总结

v4.12 原片在6分14.595秒后失败，未写出三个主视角。模型调用了未绑定的证据别名，公共读取工具抛出异常导致 SDK 中止。现在公共工具对未知引用返回可修正的精确反馈及已绑定引用；文件内容、路径和哈希异常仍严格拒绝，不能把模型拼错引用当成允许读取任意文件。

同轮新闻片产出了完整报告，三篇正文与通过暂存的对象逐项相同。独立审阅确认金额口径、平台归属和相邻推广画面的不同用途有实质改善。Reviewer 指出一处旅行示例条件遗漏；修订虽然产出通过结构校验的草稿，却因 OCR 全文尚未读完而失败，整个流程仍是待审状态，用时23分37.329秒、77次请求。不能将已经能读的原候选与未完成的修订混为成功。

审阅阶段35次请求、约5分42秒，其中16次分页读取 OCR；修订阶段20次请求、约2分44秒。新版 `read_reviewer_context`、`read_repair_context` 一次提供完整且经校验的必需文本和概览像素，JSON仅压缩空白。超出容量则不计部分已读，并明确指出续读位置。修订工具在消耗草稿校验次数前检查输入已读，避免把缺读留到末尾。改善目标是减少证据获取往返，仍需完整实跑证明收益。

新生成报告必须由 Builder 亲写 `builderLenses.finalSummary`，并使用 `summaryContractVersion: single-post-summary@1`。内容、编导、剪辑、可复用经验及条件、实际表现、未知和限制都在报告末尾展示。三篇正文仍独立完整；宿主只组合精确对象，API/UI不改写结论。历史报告无该字段时照常显示，不代写补全。后续修订不能删除新报告的总结或悄悄降级契约。

表现层逐项核对冻结来源的点赞、收藏、评论、分享、采集时间与发布标签。缺失保留 null，真实零保留零；没有同口径对照语料时比较字段保持空。Builder解释数据能支持什么、不能支持什么，Reviewer核查其归因边界。点赞不能单独证明某个切镜导致完播、或某条广告实现转化。

用户随后要求以适合模仿制作的高赞作品补充验证，广告与非广告均覆盖。选择记录同时保留互动记录的时间、广告分类证据与不确定性、制作成本及借鉴理由。以历史冻结数据筛选时明确其历史口径；品牌出现不自动等于商业广告，未证明合作关系的样本不能充作已确认广告。原有多题材测试保留，但低赞技术测试片不再充作高赞模仿案例。


## v4.13 中断与 v4.14 选样

v4.13 在5分12.537秒、17次请求后没有形成正文。第二轮第11次请求收到 HTTP200，已收至少1,363字节后自然结束，但没有最终完成事件；日志没有该轮文本增量或工具调用。不能把它判为本地断网，也没有足够输入规模记录证明服务端容量限制。SDK将这种未完成EOF纳入既有单次传输/服务端恢复预算；明确失败事件与已经对外输出文本仍不重试，完成的工具不重放。

同次trace显示Builder把疑难核对扩展成连续8秒窗口逐段扫描。提示词v4.13明确由尚未解决的问题选择窗口，保留原始密集帧对短字幕的核对能力；全片覆盖依靠完整源文、全片概览和针对问题的补证，不能靠机械追加每个近似帧来替代理解。

v4.14除143秒同片基准外，加入产品商业推介和研究演示两条高赞样本。冻结语料内按点赞选高位、排除同题重复，并结合可复做的制作结构；同作者名次只用于选样，不传入缺少对照输入的Builder，也不推断剪辑引起互动。商业推介表达可由卖点、场景、购买页面与行动号召确认；付费合作状态另列未知。低赞产品推介可留作将来的对照，不能冒充高赞样本。方法冻结后原片单独执行，新增两条最多并发二，分别记录耗时条件和成品质量。

三个完整流程均结束，三篇主文及结尾综合总结均已由 Builder 生成，API 与文件中的总结逐项相同。基准片10分30.673秒、33次请求；商业推介26分38.232秒、56次请求；研究演示23分25.949秒、44次请求。全部使用冻结本地媒体，耗时不含下载；后两片最多两条并发。基准片相对旧版29分41.906秒缩短约64.6%，但跨片速度仍不稳定，不能宣称已经达到成熟快速流水线。
