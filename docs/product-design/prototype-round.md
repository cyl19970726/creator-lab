# 历史原型第一轮：观察与未满足的设计基础

[返回产品设计](README.md) · [当前页面线框](wireframes.md) · [查看历史原型](../../prototypes/workflow-workbench/index.html)

**本原型已停止推进。** 2026-10-09 用户指出：内容布局应承接已使用的 Archify 画布与点击详情，随后明确保留整体逻辑，只需用线框解释各页及推导原则。原型另做了流程卡片和关系图，没有落实既有交互基础；作者与独立审阅者都遗漏了这一项已知要求。下列局部观察仍保留，但不能作为整体形态已获接受的依据。当前设计以[静态线框](wireframes.md)为入口。

本轮开始于 2026-10-09。目标是检验上一轮认知推导能否成为连续可操作的路径，不接入生产前端，也不运行真实模型。原型使用合成案例，操作只保存在浏览器本地；预期输出、实际资产与操作意图分别表达。

## 本轮交付与验收

| 交付 | 结束时应能作的判断 | 状态 |
| --- | --- | --- |
| 可进入准确版本的工作台外壳、方法图、案例与关系、评价和谱系 | 解释一版为何产生、实际做过什么、下一版依据是什么；能来回追溯 | 已制作；完成合成范围的界面走查 |
| 实际历史与验证计划 | 区分成功例、失败、未评和未开始，判断是否已有足够采用依据 | 走查能辨认四个计划项及计划外 R2 |
| 材料不足与采用版不可执行的操作 | 保留原事实，说明下一项决定及其影响，不伪造恢复或自动采用 | 读取与本地操作核对完成；不代表真实执行器行为 |
| 首版草案与第一项委托入口 | 从目的、材料与标准形成可检查草案，明确尚缺的执行条件 | 发现跳转丢失草案关联，修复后回归；业务方法设计本身仍未验证 |
| 独立 Agent 只凭 UI 完成任务 | 记录判断、可见依据、找不到的信息和误判；与数据事实分开核对 | 四项任务已走查；首版关联额外回归一次 |

评分公式、真实暂停恢复、自动派发、模型效果与业务价值不由本原型证明。真实 CONTENT 任务仍是后续验证；本轮不会把合成结果当成业务成果。

## 走查方式

核对者先从目标独立提出任务，不读原型源码或 fixture，不接受导航提示。通过界面完成首版形成、交付追查、改进判断和接手继续使用，说明依据与未知。负责人另查引用和范围计算；UI 无法取得的信息不得用源码答案回填为走查通过。

## 本轮观察与后续决定

核对者在看到实现前独立给出四项任务，只用浏览器读取和操作原型，没有读取源码或 fixture。另一个核对者检查合成数据与图中关系语义。以下观察支持的只是此原型和此样本范围内的判断。

| 任务 | 实际取得的认识与操作 | 限制或修订 |
| --- | --- | --- |
| 从新目标形成首版 | 填写用途、材料缺口、标准和自主边界，保存草案；界面说明预期产物与执行条件尚缺 | 起始结构是明确标注的模板，未由业务推理生成完整可执行方法。首轮还发生了下述关联错误 |
| 追查 Case A 的交付 | 跨版本读到 R1/v1 缺材未成稿，R2/v1 补材后独立完成且有评，R3/v2 完成未评；跨版本集合 8 份资产，聚焦 R1 为 3 份 | 交付、声明与核查不同；无法由输入绑定证明模型已理解。没有真实执行可验证 |
| 判断下一轮怎样改 | 看见 P 的 4 项中 R1 失败、R3 未评、R4 有评、B/v2 未开始；R2 在计划外；保存补验证的模拟判断 | 不从成稿归因关口有效；无总评分规则，时间费用和长期人工负担未测量 |
| 接手继续使用 | 从谱系读到 v1→v2 的问题、假设和验证；辨认 v1 已采用但不可执行，v2 可试跑但未采用 | 合成数据仅有一条后继，未验证多分支与大量历史；不能把可执行候选自动当采用版 |

### 实际发现的断点及修复

1. **从首版草案到委托时丢失对象范围。** 首轮核对者保存了新目标草案，但点击准备首项委托后沿默认值选择了既有 CONTENT v1。作者复核操作结果时发现这并没有承接刚才的草案；核对者确认自己误把“没有伪造运行”当成整条任务成立。修复后，此入口默认选择准确草案，保存委托时保留其身份、目标、标准和自主边界。独立回归实际保存了 `draft-1` 的冬季提醒委托；后来编辑为 `draft-2` 的春季报名草案，旧委托仍保留 `draft-1` 的原内容，没有跟随变化。
2. **对照资产被泛称为来源。** 聚焦 R3 时，其关联的 R2 稿只是供比较；“范围外关联来源”会暗示它参与生产。已改成“范围外关联资产”，关系区分回应缺口与对照，图中对照线不画生产箭头，并提供证据详情。
3. **当前阅读范围与所选运行可能混淆。** 全局任务不再沿用查看版本的采用徽章；Case 头部明确跨版本／单版本范围和当前聚焦 run。详情展开及长文滚动保留主体范围。

负责人另行通过界面核对了两项本地动作：向 R1 保存追加材料后，原输入、失败状态和 3 份原资产保持不变，后续尝试未启动；显式选择 v2 并保存候选试跑意图后，既有采用仍为 v1，没有产生新 run。浏览器关闭后仍可恢复本地模拟记录；页面上可重置这些模拟操作。

文件语法、合成引用与计划算术检查完成，文档站构建及内部链接检查通过。这些技术检查不证明设计易用或业务有效。

### 这次更新了什么认识

“对象有准确身份”还不够，**身份和业务目的必须跟随发起下一步动作，并在保存结果后可核对**。列表和详情的静态阅读正确，仍可能在默认选项、上下文切换或保存时丢失关联。另一个认识是，审阅者完成动作不代表整个任务正确：需要检查最终委托究竟属于哪份方法，而不仅是有没有错误提示。

### 由用户反馈修正的取舍

停止扩展这套原型，改用静态线框说明已认可的产品逻辑怎样承接现有 Archify 工作台。线框逐页表达主体、选择详情、上下文和下一步，不实现新的交互前端。后续建设再用真实 CONTENT 证据核对输入、实际方法、产物、评价和决定，区分未保存、接口缺失和展示问题；本记录不自动授权把全部菜单接入生产。

首版方法形成目前只验证了目的、草案和委托的衔接；业务专用节点设计、工具与资产合同的编辑、真实试跑仍是明确未覆盖项。自动采用、真实暂停恢复、评分机制、多分支大图、移动端与真人可用性也未通过本轮验证。下一轮真实运行仍需分别报告成果是否有用、自主执行是否可靠、用户解释和救场是否减少。
